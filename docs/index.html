Skyrim & Creation Engine RE infrastructure

Stop hand-typing structs the community already reverse-engineered.

If you've opened Ghidra to a stripped SkyrimSE.exe and hit FUN_1401e1270(longlong *param_1, undefined8 param_2) -- this toolkit turns fifteen years of community RE (CommonLibSSE-NG, meh321's Address Library, SKSE) into versioned, reproducible, public infrastructure: real type archives, CI-built distribution, and live runtime instrumentation.

For: RE researchers, SKSE plugin authors, engine-level patchers. Not for: gameplay mods, quests, or asset packs -- this is infrastructure other tools build on.

What is this, exactly?

The Skyrim modding ecosystem has spent fifteen years mapping the Creation Engine. That knowledge lives in CommonLibSSE-NG's headers, meh321's Address Library, and a handful of pinned Discord attachments -- this project's goal is to turn it into versioned, reproducible, public infrastructure instead of tribal knowledge.

Design principle: we do not reverse-engineer the game from scratch. We instrument, package, and distribute the knowledge the community has already produced.

Three subprojects, one pipeline

1. type-importer working MVP

Parses CommonLibSSE-NG C++ headers with libclang and emits real Ghidra type archives (.gdt). This is the engine room -- everything else builds on it.

Details →

2. symbol-archive release published

CI-driven builds that publish pre-built .gdt archives per Skyrim runtime (AE/SE/VR), so you don't have to run the pipeline yourself.

Details →

3. runtime-harness three verified live, one known non-working (off by default)

SKSE plugins that hook the AI scheduler, Havok physics, and savegame serializer for live state inspection -- RE-internals visibility, not gameplay-object tooling (see e.g. SkyLink AI/SkyrimNet for the latter).
