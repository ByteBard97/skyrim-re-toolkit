symbol-archive

early scaffold   CI-driven builds of .gdt type archives for every supported Skyrim runtime, so you don't have to run the pipeline yourself.

The problem

Every time Bethesda ships a patch, class layouts shift, the Address Library format changes (ask anyone who hit Unsupported address library format: 5 on 1.7.99), and the community's accumulated Ghidra databases go stale. There is no canonical, versioned archive of pre-built type files you can just download.

The solution

A GitHub Actions workflow that wraps type-importer's pipeline, runs a full-namespace sweep of CommonLibSSE-NG/include/RE/ per runtime, and publishes each resulting .gdt as a build artifact — with opt-in publishing to a versioned GitHub Release.

Status: matrix wired, not yet live-verified

3runtimes matrix-built: AE, SE, VR
2distribution paths: workflow artifact, or opt-in versioned GitHub Release

Runtime coverage mirrors type-importer's own CI matrix now that AE, SE 1.5.97, and VR 1.4.15 layouts are validated. AE 1.7.99/GOG need no separate build entry — they share AE 1.6.1170's macro and Address Library ID scheme.

Not yet live-verified end to end. The SE/VR matrix legs were YAML-validated (python3 yaml.safe_load) but haven't been run for real yet, since the shared parser submodule was mid-use by other work at the time — needs a follow-up manual-dispatch run to confirm the SE/VR legs actually build clean.

Accuracy: read this before trusting a class blindly

Not every class in this archive is byte-accurate. type-importer's own coverage sweep tracks this precisely — as of the last full sweep, 2,030 of 3,017 checkable classes (67%) resolve byte-accurate; the rest are either a wrong size or resolve empty.

A curated hotspot list of 39 commonly-modded classes (TESForm hierarchy, Actor/Character/PlayerCharacter, inventory, item types, quests/packages, Havok, etc.) is a much stronger accuracy signal than the archive's raw class count — that list is fully closed: 37/39 are exact, and the remaining 2 have real inferred sizes rather than silent 1-byte placeholders.

Still don't treat every struct in this archive as trustworthy without cross-checking against a real static_assert or independent verification outside the hotspot list — that remains true until type-importer's overall pass rate is much higher. See type-importer's accuracy section for what's tracked and how.

How the build works

  1. list_re_headers.sh enumerates every RE/*.h header (minus CommonLibSSE-NG's own umbrella header, which pulls in a real SKSE PCH that collides with the layout-only stub used for parsing).
  2. generate_gdt.sh patches the vendored parser extension (18 accepted fixes/features, see type-importer), builds it, and runs the patched parser against the full header list once per matrix runtime.
  3. Each resulting .gdt is uploaded as a build artifact, named per runtime.

What this buys you, visually

See type-importer's before/after screenshots — a real .gdt from this same pipeline applied to a real SkyrimSE.exe in Ghidra, showing typed field access instead of raw offsets.
